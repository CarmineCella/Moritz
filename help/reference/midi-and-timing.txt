# MIDI and timing: notes and controllers in and out, clocks, delays, ramps, loadbang

@ metro
syntax: metro [interval]
Outputs a bang at a regular interval while it runs; the first bang comes at
once. Ticks are scheduled at absolute times, so they don't drift. A new
interval, in the right inlet, is used from the next tick on: the bang already
scheduled comes first.
arg interval: the time between bangs in milliseconds, at least 1 (500)
msg bang: starts it (or restarts it, with a bang now)
msg start: the same as bang
msg number: not 0 starts it, 0 stops it
msg stop: stops it
see: delay counter line random makenote

@ delay del
syntax: delay [time]
Outputs a bang a given time after it gets one. A bang while it waits starts
the wait again, so only one bang comes out. The right inlet stores the time
for the next bang.
arg time: the delay in milliseconds (0)
msg bang: starts the wait (or starts it again)
msg number: sets the time and starts the wait
msg stop: cancels the bang still to come
see: metro makenote trigger line

@ line
syntax: line [start] [grain]
Control-rate ramps: target time goes from the current value to target in time
milliseconds, outputting a value every grain milliseconds (the first one at
once). A number alone jumps there, or ramps over the time set in the middle
inlet, which then goes back to 0, as in Max. The right inlet sets the grain.
To ramp a signal (an amplitude, a frequency) without steps, use line~.
arg start: the value it starts from (0)
arg grain: milliseconds between outputs during a ramp, at least 1 (20)
msg target time grain: ramps to target in time ms, and sets the grain
msg target time: ramps to target in time ms
msg number: jumps there, or ramps over the time set in the middle inlet
msg set x: stops any ramp and sets the value to x, without output
msg stop: stops the ramp where it is
see: line~ metro scale delay

@ loadbang
syntax: loadbang
Sends a bang when the patch opens: use it to set starting values. A bang in
its inlet, or a double-click on it in locked mode, fires it again.
msg bang: fires it again
see: metro message send delay

@ notein
syntax: notein [channel]
Notes from a MIDI keyboard or controller (the device is chosen in Patch >
MIDI Setup). Outputs pitch and velocity, a velocity of 0 for a note-off, and,
without a channel argument, the channel, from right to left: the pitch comes
last.
arg channel: 1 to 16 to listen to that channel only; 0 or none for all channels, with an outlet for the channel (0)
see: noteout stripnote makenote ctlin mtof

@ ctlin
syntax: ctlin [controller] [channel]
Control changes from MIDI input. Outputs the value, 0 to 127, then the
controller number (only without a controller argument) and the channel (only
without a channel argument), from right to left: the value comes last.
arg controller: 0 to 127 to listen to that controller only; none, or a number outside, for all (all)
arg channel: 1 to 16 to listen to that channel only; 0 or none for all (0)
see: ctlout bendin pgmin notein scale

@ bendin
syntax: bendin [channel]
Pitch bend from MIDI input, as 0 to 127 with 64 at the centre (the coarse
part of the bend, as in Max). Without a channel argument a second outlet gives
the channel.
arg channel: 1 to 16 to listen to that channel only; 0 or none for all (0)
see: ctlin pgmin notein scale

@ pgmin
syntax: pgmin [channel]
Program changes from MIDI input, as 1 to 128. Without a channel argument a
second outlet gives the channel.
arg channel: 1 to 16 to listen to that channel only; 0 or none for all (0)
see: ctlin bendin notein

@ noteout
syntax: noteout [channel]
Sends MIDI notes to the output chosen in Patch > MIDI Setup (by default the
virtual port Moritz, which a synth or DAW can listen to). A pitch in the left
inlet sends a note with the velocity last set in the middle inlet; velocity 0
is a note-off. The velocity is 0 until it is set, so set it first, or send
pitch velocity. Values are clipped to 0-127.
arg channel: the MIDI channel, 1 to 16 (1)
msg number: sends a note with that pitch and the stored velocity
msg list pitch velocity: sets the velocity and sends the note
see: makenote notein ctlout kslider

@ ctlout
syntax: ctlout [controller] [channel]
Sends MIDI control changes to the output chosen in Patch > MIDI Setup. A
number in the left inlet sends that value, clipped to 0-127, to the
controller and channel set by the arguments or the other inlets.
arg controller: the controller number, 0 to 127 (7, volume)
arg channel: the MIDI channel, 1 to 16 (1)
msg number: sends it as the controller's value
see: ctlin noteout scale

@ makenote
syntax: makenote [velocity] [duration]
Makes a note-on now and its note-off later: a pitch in the left inlet goes out
at once with the velocity, and again with velocity 0 after the duration. A
velocity of 0 sends only that, with nothing scheduled. Velocity and duration
can also be changed in the other inlets.
arg velocity: the velocity of the note-ons, 0 to 127 (100)
arg duration: the time to the note-off, in milliseconds (250)
msg number: outputs the pitch with the velocity, and schedules its note-off
msg list pitch velocity: sets the velocity, then the same
msg stop: sends the pending note-offs now
msg clear: forgets the pending note-offs, without sending them
see: noteout stripnote poly~ metro delay

@ stripnote
syntax: stripnote
Passes note-ons and drops note-offs: a pitch in the left inlet goes out, with
the velocity last set in the right inlet, only when that velocity is above 0.
Outputs go right to left: velocity, then pitch.
msg number: passes the pitch, with the stored velocity, when it is above 0
msg list pitch velocity: sets the velocity, then the same
see: notein makenote select kslider

@ transport
syntax: transport [bpm] [num den]
The patch's clock: where its scores are and whether they play. There is one
for each patch open in a window of its own (with its subpatches and
abstractions; a help patch has its own, and so has a score opened from a file):
every transport object in it shows and drives the same clock, and every score
object in it plays on it, while another patch open plays and stops on its own.
Times in a score are seconds; bars and beats are counted at the tempo, in beats
a minute (a beat is 1/den of a bar), and the meter.

A change takes effect on the sample a message sent now lands on, as every timed
message in Moritz: a score's sounds start on their sample, and its notes leave
it at the time whose sample is theirs. The bar, the beat and the position in ms
come out at every beat while it plays and at every change.
arg bpm: the tempo, beats a minute (120)
arg num den: the meter, also written 3/4 (4 4)
msg play: starts from where it is (also start, or a number not 0)
msg stop: stops where it is (also 0)
msg locate bar [beat [tick]]: goes to a bar (from 1; 480 ticks a beat)
msg seek ms: goes to a time in milliseconds
msg rewind: goes to the start
msg loop bar1 bar2: plays from bar1 up to bar2 again and again, once it is before bar2; loop 0 (or off) ends the loop
msg tempo bpm: the tempo bars and beats are counted at
msg meter num den: the meter
msg bang: the position now
see: score metro

@ score
syntax: score name [file.score] [channels] [@size w h] [@view timeline|roll|piano|list]
A score that plays itself on the patch's transport: notes, sounds, messages
and other scores placed in time. It is Musil's score (the same C++ structure),
read from a .score file, written by Musil's score-write or by a code box that
sends one with (out 1 s); a .score file is Musil data, read without running
anything. Without a file the score is kept in the patch.

Its sounds (regions of a file or of a buffer~, by name) come out of its signal
outlets, each on its sample, placed at its azimuth (one channel: all of it; two:
equal power, as Musil's pan-azimuth; more: a ring of speakers); the scores
inside it are played at their place, stretched, transposed and turned. Its notes
come out as lists, pitch (MIDI, with the cents) velocity (from the dynamics)
duration in ms, row, dynamics and technique (- for none); its messages as the
name and the values. Edits while it plays (add, clear, a new score) take effect
at once: what plays is made again off the audio thread. A note that carries a
sound of its own (data sound "path", and sound-pitch, the sample's pitch: what
orchidea sends) also plays its sample, faster or slower by its pitch against the
sample's.

The box draws its score as a roll: a staff a row (in orchestral order, a G, F
or C clef from its pitches, drawn as a shape), proportional time, a note a head and a line, its cents when it
is detuned (a microtone, or orchidea's cents: always shown, in the box a small
number by the head, or a tick above it when the box is too small); scores placed
inside as faint blocks with their placement; sounds, patches and messages on
lines of their own; the transport's position. When the patch is locked it is
edited in place: click a note (Shift adds, a rectangle selects), drag it (later
or earlier on the grid, higher or lower on the staff), drag its end to resize it,
Alt-drag copies, Delete takes the selection out, the arrows nudge it (Shift: a
bar, an octave), Alt+Up and Alt+Down detune it by a cent (Shift+Alt: ten cents),
Q quantizes it. In edit mode the corner at its bottom right sizes it.

A double-click (or its menu's Open, or open) opens the score's window: one window
for the score, whose views are switched at its top, in place: Timeline, Roll,
Piano roll and List, with one transport bar (to start, Play, loop, the position),
one breadcrumb and one status line; switching keeps the selection, the playhead
and the time shown. It opens in the view used last for the score; the first time
in the box's @view (Roll when it has none). Play plays the score from the
playhead, or from the start of what was selected after the playhead was placed,
locating the transport first, whatever it was doing; pressed again (or Space,
whatever is selected) it stops; the playhead at the score's end or past it, Play
starts from the start (past the loop, from the loop's start). A play started
there stops at the score's end (unless it loops) and the playhead goes back where
it started; a play started by a transport object goes on as the patch's clock,
and the window shows its score playing only while the transport is inside it. The
button always shows what the transport does. Play starts the patch the score's
box is in (a score of its own, from a file or placed inside another, plays on a
player of its own): another patch open does not start. With the audio off, Play
says so. In real time a play is heard two of the device's buffers after it is
pressed, as every timed message.

The Roll view: staves, a piano roll or a list of the events (each cell edited, the
cents too), a lane of dynamics (its row chosen at its left), the score as Musil
data (edited and kept in sync: nothing applied while it does not read), Select /
Draw / Erase, snap, quantize, the Transform panel (transpose, invert, retrograde,
augment, diminish, quantize, humanize, thin, density: Musil's score-transpose! and
the others, the same functions); a double-click on a score placed enters it (all
its placements follow its edits), Esc goes up.

A click on a note (not a drag, not with Shift) sounds it, in the box and in the
window (audition): a note with a sample of its own (orchidea's) plays it at the
note's pitch for its duration through the sound editor's preview; a note without
one leaves the notes outlet as playing sends it, then at its end the same with
velocity 0, so the patch's synth plays it (with nothing connected there, as a
tone); a sound event plays its region. The roll's Audition button turns it off
(for every roll); the transport is never started, and with the audio off the
status line says so.

Its rows are tracks. A track's mixer strip (gain, pan as an azimuth, mute and
solo, kept on the row in the score) applies to the sounds, notes and patches on
it, and to the scores placed on it: a muted track is silent, and when a track is
soloed only the soloed ones sound. A sound's fade-in and fade-out are played. A
message is also sent to the receive objects of its name, so an automation lane
drives a patch's receive; messages are sent whatever the strip says.

The Timeline view: tracks with their clips (sound regions drawn as waveforms,
notes, scores placed inside, patch clips) and automation lanes, an inspector,
snap to beats and bars, cut, copy, paste and undo, Render to a WAV file. Each
track and lane is as high as its lower edge is dragged (a double-click there folds
it to one line and back; Alt: every one), kept in the score. A click on a track's
name opens what it plays (a sound clip's sound in the sound editor with the
clip's region selected, a patch, a score placed) or, for its lanes, the patch that
receives them with those receive objects selected (a lane's name: its own); a
sound clip double-clicked opens its region too. File > Open Score... and File >
New Score open a .score file on its own the same way; a score placed inside
another opens in its own window, with a breadcrumb to where it is.

A stereo sound on two outlets is balanced by its azimuth (the clip's and its
track's), as a mono one is panned. The box's roll and its window's views are views
of one score: an edit in one is in the others at once, with one undo history and
one selection.
Every edit plays at once. A score kept in the patch is saved with the patch: its
edits mark the patch edited, and they are undone in the score's history (Edit >
Undo with the box clicked last, or the roll's or the timeline's Undo), not as
steps of the patch; a message to the box (add, clear, read, a transformation, a
score sent), the code view or the patch's Undo (which puts back the whole patch as
it was before its step, its scores too) change the score from outside, and its
history starts again from there. A score with a file of its own is written by
Save in its window (closing it with unsaved edits asks). A score replaced whole
(clear, read, a score sent) forgets the selection.
arg name: the score's name
arg file.score: a file next to the patch to read the score from (none: kept in the patch)
arg channels: the signal outlets, 1 to 16 (2)
arg @size w h: the box's size (360 by 150)
arg @view v: the view its window opens in the first time: timeline, roll, piano or list (roll)
msg read [file]: reads a .score file (its own again without a name)
msg write [file]: writes it as a .score file, in the patch's folder or in ~/Documents/Moritz; the scores it places and its sounds are named from the file's folder (relative when near, else absolute), so it reads back whole
msg clear: no events
msg add note at dur row pitch [dyn [tech]]: a note (at and dur in seconds; the pitch a MIDI number or a name, G5)
msg add at row pitch [dyn [tech]]: a note a beat long (the kind and the duration may be left out)
msg add sound at dur file: a sound file's region
msg add msg at name values: a message
msg select all | none | id... | row name | time t0 t1: the events the transformations change (none: all of them); the same selection as its roll and its timeline
msg transpose n: the notes (and the scores placed) n semitones higher
msg invert [pitch]: the notes mirrored around a pitch (none: the middle of their pitches)
msg retrograde: backwards within their span
msg augment k: onsets and durations k times longer, from the first onset (diminish k: k times shorter)
msg shift seconds: later (earlier when negative; never before 0)
msg quantize [grid [strength]]: onsets and ends toward the grid in seconds (the roll's snap, 1/16), by strength (1: onto it)
msg humanize [ms [dB [seed]]]: onsets moved at random by up to ms (20), gains by up to dB (1.5)
msg thin keep [seed]: each event kept with probability keep
msg density v...: each event kept with the probability the curve v... has at its onset
msg open [view]: its window, in that view (timeline, roll, piano, list; none: the view used last)
msg play: starts the patch's transport (every score of the patch plays) from where it is, or from the start when it is at this score's end or past it; a play sent here stops at the score's end, unless the transport loops or something else started, stopped or moved it since
msg stop: stops the transport
msg locate bar [beat]: moves the transport
msg seek ms: moves the transport to a time
msg info: rows, events and seconds out of the info outlet
msg score token: the score a code box (or orchidea) sent
see: transport code buffer~ receive orchidea
